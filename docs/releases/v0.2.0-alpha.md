# Glicia v0.2.0-alpha

Data: 30 de agosto de 2026.

A `v0.2.0-alpha` prepara a Glicia para receber uma interface mobile-first sem abandonar a CLI
que já demonstrou valor. Esta é uma release de arquitetura, contratos e testabilidade: não há
mudança intencional na fórmula, no arredondamento, nas travas clínicas ou no fluxo apresentado à
pessoa usuária da CLI.

## Destaques

### Monorepo para múltiplas interfaces

O repositório agora separa aplicações e recursos compartilhados:

```text
apps/
├── cli/                    # aplicação Python atual
└── pwa/                    # futura aplicação React/TypeScript
packages/
└── contracts/              # schemas e fixtures entre linguagens
docs/                       # documentação do projeto
```

A PWA possui apenas o manifesto inicial nesta versão. Ela ainda não oferece uma interface web
funcional.

### Núcleo Python desacoplado

A CLI foi dividida em responsabilidades explícitas:

- `domain`: tipos, cálculo e segurança determinísticos;
- `application`: coordenação da sessão e porta neutra de IA;
- `clients`: OpenAI, prompt e integrações externas;
- `persistence`: preferências e histórico SQLite;
- `presentation`: fluxo e componentes do terminal.

O domínio não conhece OpenAI, Rich, SQLite ou detalhes do terminal. Um teste arquitetural impede
que dependências das camadas externas sejam introduzidas no núcleo.

### Contratos de conformidade

`packages/contracts` contém JSON Schemas e casos fictícios que podem ser executados tanto pela
CLI Python quanto pela futura PWA TypeScript. A primeira versão cobre:

- configurações clínicas;
- turnos estruturados da conversa;
- cálculo determinístico de dose;
- arredondamento final;
- ajuste por tendência;
- bloqueio por hipoglicemia e alerta de queda rápida;
- formato do registro de refeição;
- erros neutros de fornecedores de IA.

Esses contratos verificam equivalência de comportamento sem obrigar Python e TypeScript a
compartilharem código executável.

### Sessão e fornecedor de IA testáveis

O fluxo de coleta, correção e confirmação saiu da camada de terminal. A aplicação agora expõe uma
porta neutra de IA, enquanto detalhes exclusivos da OpenAI, como `previous_response_id`, ficam no
adaptador do fornecedor. Os testes usam um fornecedor fake e não precisam de rede ou chave real.

### Segurança determinística isolada

As decisões de bloquear o cálculo por hipoglicemia e alertar sobre queda rápida foram extraídas
da interface. Elas continuam locais e determinísticas e agora possuem testes próprios e casos de
conformidade compartilhados.

## Impacto para quem usa a CLI

O comportamento esperado permanece o mesmo. A instalação a partir do repositório mudou por
causa do monorepo:

```bash
python -m pip install -e apps/cli
```

O comando continua sendo `glicia`, e `python -m glicia` também permanece disponível. Dados
locais continuam em `~/.glicia/`, e a chave da OpenAI continua sendo fornecida por
`OPENAI_API_KEY` sem ser salva pelo programa.

## Impacto para contribuidores

- Código Python: `apps/cli/src/glicia/`.
- Testes Python: `apps/cli/tests/`.
- Manifesto do pacote Python: `apps/cli/pyproject.toml`.
- Contratos compartilhados: `packages/contracts/`.
- Configuração de Ruff, Mypy e Pytest: `pyproject.toml` na raiz.
- Ambiente de desenvolvimento: `python -m pip install -e "apps/cli[dev]"`.

CI e Dependabot foram atualizados para os novos caminhos. O wheel Python continua incluindo a
tabela nutricional e os módulos internos da CLI.

## Qualidade

- 41 testes automatizados aprovados;
- schemas JSON validados como Draft 2020-12;
- fixtures executadas contra a implementação Python;
- Ruff e verificação de formatação aprovados;
- Mypy aprovado;
- wheel e instalação editável verificados;
- comando `glicia` verificado após a reorganização.

## Limitações conhecidas

- A PWA ainda não possui interface navegável ou instalação no celular.
- O único fornecedor implementado continua sendo a OpenAI.
- A chave ainda é configurada pela variável de ambiente na CLI.
- Exportação, importação e backup ainda não foram implementados.
- Não existe integração direta com FreeStyle Libre, LibreLink ou LibreView; a glicemia e a
  tendência continuam sendo informadas manualmente.
- O aplicativo não calcula insulina ativa e não substitui o plano individual ou a equipe de
  saúde.

## Próximo passo

A `v0.3.0` deverá criar o protótipo mobile-first em `apps/pwa`, portar o domínio para TypeScript e
executar os mesmos contratos antes de conectar a interface a um fornecedor real de IA.
